Quick start: verify a WAV transfer

Start with a lossless file before testing an unknown live-audio route.

  1. Build the workspace. The bootstrap CLI packages text into an ADLP v1 object and creates mono 48 kHz PCM WAV.
  2. Move the WAV file. Any ordinary file channel can carry this first reference transport.
  3. Decode and verify. The receiver checks framing and final ADLP integrity before returning the object.

CLI / bootstrap

cargo run -p adlp-cli -- encode-text hello.wav N1 "Hello from AudioModem" reliable
cargo run -p adlp-cli -- decode hello.wav

The bootstrap mapper is intentionally simple. It is not a robust over-the-air acoustic modulation scheme.

Protocol

Versioned object, not a route

ADLP defines the object before a physical profile turns it into PCM. A future Acoustic-1 profile changes the mapper, not the wire object.

ADLP v1 specification ↗
Explicit trust boundary

A callsign is open display metadata, not identity proof. Encryption and key exchange require a future public RFC and security review.

Transmission presets

A profile ID travels inside the manifest. The preset expresses a user-facing speed–reliability intent but does not change the ADLP wire object.

PresetIDIntentBootstrap behavior
Reliable1Noisy or unknown pathShared bootstrap mapper
Balanced2Practical starting pointShared bootstrap mapper
Fast3Clean line or WAV pathShared bootstrap mapper
Narrowband4Future radio profileShared bootstrap mapper

Contributing

AudioModem develops protocol, DSP and cryptographic behavior in public. Compatibility changes start as an RFC; focused documentation, tests and UI corrections can start with an issue and pull request.
