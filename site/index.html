Обзор

Один формат объекта

ADLP переносит манифест, payload и контроль целостности независимо от аудиомаршрута.

Сменяемые маршруты

Модем создаёт PCM, а устройство или приложение определяет, как это аудио дойдёт до приёмника.

Явная модель доверия

Позывной — display metadata. Аутентификация и шифрование остаются отдельными будущими расширениями.

Быстрый старт: воспроизводимый WAV workflow

Начните с lossless файла до проверки неизвестного live-аудиомаршрута.

  1. Соберите workspace. Bootstrap CLI упаковывает текст в ADLP v1 объект и создаёт mono PCM WAV 48 kHz.
  2. Передайте WAV-файл. Любой файловый обмен может служить первым reference transport.
  3. Декодируйте и проверьте. Приёмник проверяет кадр и итоговую целостность ADLP до возврата объекта.

CLI / bootstrap

cargo run -p adlp-cli -- encode-text hello.wav N1 "Привет" reliable
cargo run -p adlp-cli -- decode hello.wav

Протокол и безопасность

ADLP v1 bootstrap

Текущий scope: versioned manifest, callsign, object type, profile ID, payload и CRC-32C. WAV bootstrap детерминирован и предназначен для воспроизводимых тестов.

Спецификация протокола ↗
Security posture

Начальный режим не шифруется. Позывные не являются доказательством личности. Будущие key exchange и encryption потребуют публичного RFC и security review.

Security policy ↗

Участие в проекте

В репозитории есть contribution guide, code of conduct, private security reporting, issue forms, CODEOWNERS и branch rules. Изменения совместимости контейнера или физического слоя предлагаются через RFC.
